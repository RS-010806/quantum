What the QUBO actually optimized

classical run · QUBO output

Every input becomes a binary choice: keep it or drop it. The algorithm minimizes one energy score that balances three explicit goals.

lower energy = useful inputs + less overlap + exact input limit
01 · Reward Target connection

Favor inputs that move with the outcome being predicted.

02 · Penalty Repeated information

Avoid spending the limit on inputs that tell the same story.

03 · Constraint Your exact limit

Penalize every solution that keeps too many or too few inputs.

How it chooses

Three ideas.
One clear feature set.

The result comes from a simple trade-off: keep what helps, avoid what repeats, and respect the feature limit you chose.

score = useful signalkeep + less repetitionbalance + your limitrespect
01

Measure what helps

Each feature is checked for how strongly it connects to the result you want to predict.

02

Try many combinations

The search explores different feature mixes and favors combinations that add new information.

03

Compare fairly

The chosen set is checked against a simple ranking and the full dataset using the same model and data splits.
